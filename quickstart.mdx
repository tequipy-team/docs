## Step 1: Verify your token

The simplest way to confirm your token works is to query your users list. This
is a read-only call that works with any token role.

<CodeGroup>

```bash cURL
curl -X POST https://prod.backend.tequipy.com/integration/users/query \
  -H "Authorization: Bearer $TEQUIPY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{}'
```

```python Python
import requests, os

resp = requests.post(
    "https://prod.backend.tequipy.com/integration/users/query",
    headers={"Authorization": f"Bearer {os.environ['TEQUIPY_TOKEN']}"},
    json={},
)
resp.raise_for_status()
print(resp.json())
```

```javascript Node.js
const resp = await fetch(
  "https://prod.backend.tequipy.com/integration/users/query",
  {
    method: "POST",
    headers: {
      Authorization: `Bearer ${process.env.TEQUIPY_TOKEN}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({}),
  }
);
const data = await resp.json();
console.log(data);
```

</CodeGroup>

## Step 2: Common workflows

Pick the workflow that matches your use case.

### Offboard a departing employee

When an employee leaves, create an offboarding to arrange equipment collection.
You need the employee's user ID and the IDs of the equipment to collect.

<Steps>

<Step title="Create the offboarding">

```bash cURL
curl -X POST https://prod.backend.tequipy.com/integration/offboardings \
  -H "Authorization: Bearer $TEQUIPY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "userId": "<EMPLOYEE_ID>",
    "offboardingEquipmentIds": ["<EQUIPMENT_ID>"],
    "lastWorkingDayAt": "2025-07-31T17:00:00Z",
    "pickUpDetails": {
      "fullName": "Jane Doe",
      "privateEmail": "jane.personal@example.com",
      "phoneNumber": "+49 30 12345678",
      "streetLine1": "Unter den Linden 1",
      "city": "Berlin",
      "postalCode": "10117",
      "countryCode": "DE"
    }
  }'
```

</Step>

<Step title="Track the offboarding status">

```bash cURL
curl https://prod.backend.tequipy.com/integration/offboardings/<OFFBOARDING_ID> \
  -H "Authorization: Bearer $TEQUIPY_TOKEN"
```

The `state` field progresses through:
`INITIATED` → `MATERIALS_SENT` → `COURIER_SCHEDULED` → `PICKED_UP` → `COMPLETED`

</Step>

</Steps>

### Redeploy equipment to a new hire

Send equipment from your storage to an employee's address in one API call.

<Steps>

<Step title="Create the redeployment">

```bash cURL
curl -X POST https://prod.backend.tequipy.com/integration/redeployments \
  -H "Authorization: Bearer $TEQUIPY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "employeeId": "<EMPLOYEE_ID>",
    "storageEquipmentIds": ["<USER_EQUIPMENT_ID>"],
    "startDate": "2025-08-01",
    "deliveryAddress": {
      "fullName": "Alex Smith",
      "streetLine1": "Rosenthaler Str. 40",
      "city": "Berlin",
      "postalCode": "10178",
      "countryCode": "DE"
    }
  }'
```

</Step>

<Step title="Track the delivery status">

```bash cURL
curl https://prod.backend.tequipy.com/integration/redeployments/<REDEPLOYMENT_ID> \
  -H "Authorization: Bearer $TEQUIPY_TOKEN"
```

The `state` field progresses through:
`INITIATED` → `PROCESSING` → `SENT` → `OUT_FOR_DELIVERY` → `COMPLETED`

</Step>

</Steps>

### Add equipment to your inventory

Register a device and describe it with specification parameters. The model type
decides which parameters apply, and each parameter offers a fixed set of values.

<Steps>

<Step title="List the model types">

```bash cURL
curl https://prod.backend.tequipy.com/integration/equipment-model-types \
  -H "Authorization: Bearer $TEQUIPY_TOKEN"
```

```json
[
  "LAPTOP",
  "MONITOR",
  "TABLET",
  "SMARTPHONE",
  "KEYBOARD_AND_MOUSE",
  "CABLES",
  "CHARGER",
  "ACCESSORIES",
  "HEADSET"
]
```

</Step>

<Step title="Read the parameters of that model type">

```bash cURL
curl https://prod.backend.tequipy.com/integration/specification-parameters/LAPTOP \
  -H "Authorization: Bearer $TEQUIPY_TOKEN"
```

```json
[
  {
    "id": "a1f3c8d2-4e77-4b90-9a11-6c2f8e5d4b03",
    "key": "ram",
    "name": "RAM",
    "values": [
      { "id": "3f6c1b84-2d55-4a1e-9f70-8c4b2e6a9d11", "value": "16 GB" },
      { "id": "7ab19e52-c630-4f8d-b214-59d7a0f3c862", "value": "32 GB" }
    ]
  }
]
```

Collect the `id` of every value you want in `parameterValueIds`. The registry
changes rarely, so you can cache it and refresh it once a day.

</Step>

<Step title="Create the equipment">

```bash cURL
curl -X POST https://prod.backend.tequipy.com/integration/user-equipment \
  -H "Authorization: Bearer $TEQUIPY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "MacBook Pro 14",
    "serialNumber": "C02XL0ABCDEF",
    "modelType": "LAPTOP",
    "parameterValueIds": ["3f6c1b84-2d55-4a1e-9f70-8c4b2e6a9d11"],
    "customAttributes": [
      { "name": "Colour", "value": "Space Grey" }
    ],
    "user": { "email": "jane@example.com" }
  }'
```

`modelType` is required. `parameterValueIds` is optional, and every id must
belong to a parameter of that model type. Send `customAttributes` for text the
registry does not cover — it is shown as written, and it is not filterable. Omit
`user` to place the device in your company storage instead.

</Step>

</Steps>

Serial numbers are unique per company. Creating the same serial number twice
returns an error, so you can retry a failed batch safely. Tell us when a value
you need is missing from the registry, and we add it.
